# 社区便民服务系统——新增功能设计文档

> 版本：V1.0 | 日期：2026-05-21 | 用途：工作群分发、各成员了解自己任务

---

## 一、背景

老师反馈当前系统功能偏少，需从现有 5 个业务模块扩展到 **12~13 个**。新增功能要求：

- 必须是**业务功能**，不是 RuoYi 框架自带（用户管理、角色管理、操作日志、系统配置等不计数）
- 每个功能对应一个**独立侧边栏菜单**，有独立页面
- 2~3周内完成

## 三、各功能详细说明

### 📅 预约管理（宋梓瑜）

**业务场景：** 居民电话预约办理时间 → 社区受理员在系统中排期确认

**数据库：新建 `appointment` 表**

```sql
id          BIGINT 主键
resident_name  VARCHAR(50)   预约人姓名
resident_phone VARCHAR(20)   预约人电话
service_item_id BIGINT       预约服务事项ID
appointment_date DATE         预约日期
time_slot   VARCHAR(20)      时间段（上午/下午）
status      VARCHAR(20)      状态：PENDING待确认/CONFIRMED已确认/CANCELED已取消/COMPLETED已完成
remark      VARCHAR(500)     备注
create_time DATETIME
```

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /appointment/list | 预约列表（分页+日期/状态筛选） | 登录即可 |
| POST | /appointment | 新增预约（管理员代录入或公开接口） | 免登录 |
| PUT | /appointment/{id}/confirm | 确认预约 | appointment:manage |
| PUT | /appointment/{id}/cancel | 取消预约 | appointment:manage |
| PUT | /appointment/{id}/complete | 标记已完成 | appointment:manage |

**前端页面：AppointmentManage.vue**
- 列表视图：表格 + 日期筛选 + 状态标签（待确认/已确认/已取消/已完成）
- 日历视图：用 Element Plus Calendar 组件，按日期展示预约（加分项，先做列表再做日历）
- 操作：确认/取消/完成按钮

### 🔔 消息通知（宋梓瑜）

**业务场景：** 管理员向居民发送审核结果通知（站内信形式，模拟实现）

**数据库：新建 `notification` 表**

```sql
id          BIGINT 主键
title       VARCHAR(200)    通知标题
content     TEXT            通知内容
type        VARCHAR(20)     类型：AUDIT审核通知/SYSTEM系统通知
target_id   BIGINT          关联申请ID（可为空）
target_name VARCHAR(50)     接收人姓名
target_phone VARCHAR(20)    接收人电话
is_read     TINYINT         是否已读
create_time DATETIME
```

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /notification/list | 通知列表（分页+类型/已读筛选） | 登录即可 |
| POST | /notification | 发送通知 | notification:send |
| GET | /notification/unread-count | 获取未读数量（首页红点） | 登录即可 |
| PUT | /notification/{id}/read | 标记已读 | 免登录 |

**前端页面：NotificationView.vue**
- 左侧通知列表（已读变灰，未读加粗）
- 右侧通知详情展示
- Layout.vue 顶部加红点（未读数 > 0 时显示）

### ⭐ 服务评价（梁浩琰）

**业务场景：** 申请办结后，居民对服务进行星级评价 → 管理员查看评价和满意度统计

**数据库：新建 `evaluation` 表**

```sql
id          BIGINT 主键
application_id BIGINT      关联申请单ID
score       INT            评分（1-5星）
content     VARCHAR(500)   评价内容
create_time DATETIME
```

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /evaluation/list | 评价列表（分页+评分筛选） | 登录即可 |
| POST | /evaluation | 提交评价（居民端用） | 免登录 |
| GET | /evaluation/stats | 满意度统计（总评分数、平均分、各星级占比） | 登录即可 |

**前端页面：EvaluationManage.vue**
- 上半部分：统计卡片（总评价数 / 平均分 / 好评率）
- 中间：星级分布柱状图（1星~5星各多少条）
- 下半部分：评价列表（关联申请编号、评分星星展示、评价内容、时间）

### ⏰ 超时预警（王烁幸雲）

**业务场景：** 申请超过 service_item 设定的 processing_days 未办结，自动标记超时 + 催办

**不需要新表：** 基于现有 application_form + service_item 的 processing_days 计算

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /warn/timeout-list | 超时申请列表（分页+超时天数排序） | 登录即可 |
| GET | /warn/timeout-count | 超时数量（首页卡片用） | 登录即可 |
| PUT | /warn/{id}/urge | 催办（标记+发送通知） | apply:audit |

**统计逻辑：**
```
超时天数 = 当前日期 - 申请提交日期 - service_item.processing_days
超时天数 > 0 的申请即超时
```

**前端页面：TimeoutWarning.vue**
- 超时列表：申请编号、服务事项、提交时间、承诺天数、已超时天数（红色高亮）
- 催办按钮 → 调通知接口自动发催办站内信
- **Dashboard 集成**：首页统计卡片新增"超时预警数"（王烁幸雲需在 DashboardView.vue 加一个卡片）

### 📎 材料管理（桂子璇）

**业务场景：** 管理员查看居民申请时上传的附件，可预览、可标注审核结果

**不新建表：** 使用 application_form 表的 attachments 字段（JSON 数组存储文件路径）

**后端只需新增：**
- 文件上传接口：POST /upload → 存到本地 /uploads/ 目录，返回路径
- 文件预览接口：GET /upload/{filename} → 返回文件流

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /upload | 上传附件 | 登录即可 |
| GET | /upload/{filename} | 预览/下载文件 | 免登录（图片直接展示） |
| GET | /attachment/list | 按申请单查看附件列表 | 登录即可 |

**前端页面：AttachmentManage.vue**
- 按申请单分组展示附件列表
- 点击预览（图片直接弹窗查看，其他类型显示文件名+下载按钮）
- 审核员可对附件标注"已核验/有问题"

### 🧾 居民在线申请（桂子璇）

**业务场景：** 居民自主填写申请表提交，不通过管理员代录

**不新建表：** 使用现有 application_form 表 + resident_info 表

**后端接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /apply/public | 居民公开提交申请（先查居民手机号，无则自动创建） | 免登录 |
| GET | /apply/progress | 已有（手机号查进度），需确认可用 | 免登录 |
| POST | /evaluation | 办结后评价（复用梁浩琰的接口） | 免登录 |

**前端页面：ResidentApply.vue（登录页入口进入）**
- Step1 填表：姓名、手机号、选择服务事项、填写申请内容、上传附件
- Step2 查进度：输入手机号 → 展示申请列表 + 时间轴
- Step3 评价：办结的申请可点击评价 → 星级评分 + 文字

**登录页入口：** 在 LoginView.vue 加一个"居民办事入口"按钮，跳转到 /resident/apply

## 五、注意事项

### 数据库

- 所有新表统一用 `utf8mb4` 字符集
- 建表 SQL 加到 `sql/init.sql` 末尾（不要覆盖前面已有内容）
- 表名前缀建议不加，直接 `appointment`、`notification`、`evaluation`、`guide_article`

### 后端

- Controller 按模块建子包：`controller/appointment/`、`controller/notification/` 等
- API 统一返回 `Result<T>` 格式
- 需要权限的接口加 `@RequiresPermissions`，新权限码加到 `sys_permission` 表
- Service/ServiceImpl/Mapper 按现有模式创建

### 前端

- 页面放 `frontend/src/views/` 下按模块建子目录
- API 放 `frontend/src/api/` 下按模块建 JS 文件
- 路由在 `router/index.js` 新增（放在"系统管理"分组之前）
- 所有页面继承现有 Layout.vue 布局

### 权限码新增

在 `sql/init.sql` 的 `sys_permission` 插入语句后追加：

